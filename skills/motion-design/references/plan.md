## brief.md (director packet)

Keep it tight. Hire a crew; do not describe "vibes".

1. **Logline** — film in one line, plus the joke or claim every decision is checked against
2. **References** — frames, sites, films; keep vs push
3. **Constraints** — format, duration, fps, fonts you actually have, no-invented-claims
4. **State list** — if the film is a UI morph or one-shape piece, list every state the object occupies and the cursor/action that causes each change. Last frame equals first if `--loop`
5. **Text on screen** — when type is huge, when it is a caption, and the space reserved for it
6. **Workflow gates** — plan → stills → critique → fix → encode. Do not skip
7. **Deliverables** — `reel.mp4`, `reel.jpg`, `share-copy.txt`, `critique.md`

## Reading-time math

Hold floors, counted from the moment the whole line is on screen and settled:

- 1–3 word label — 0.8s
- Headline / sentence — 0.3s per word, minimum 1.2s
- Hook line — give it the most

Entrances stay snappy (0.3–0.6s). Fast-in plus a real hold reads as punchy and legible. If a 4s scene is carrying six readable lines, cut copy or split the scene. Do not speed the type up.

Beat-grid reveals ~0.5s apart are fine for ticks and glows. Too fast for readable lines — snap text to every other beat, or reveal quickly and hold the full set.

## What to show (preferred order)

1. Working-app moment with real-looking content
2. Recreated UI chrome using real tokens and copy
3. The core concept as a graphic (only if there is no UI)
4. Type-forward sequence (only if the product *is* the copy)

Never fill a scene with an abstract wash that could belong to any brand.
